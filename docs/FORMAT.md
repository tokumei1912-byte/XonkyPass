# Формат хранилища XonkyPass

Описание файла `vault.xpv`: как он устроен, что в нём зашифровано и от чего это защищает.
Код — в [`crates/core`](../crates/core/src), схема БД — в [`crates/core/migrations`](../crates/core/migrations).

| Версия                         | Значение | Где задаётся                                      |
| ------------------------------ | -------- | ------------------------------------------------- |
| Формат (шифрование, AAD)       | 1        | `FORMAT_VERSION` в `lib.rs`, колонка `vault.format_ver` |
| Схема БД                       | 1        | число миграций, `PRAGMA user_version`             |
| JSON содержимого записей       | 1        | поле `v` в метаданных и в снимках истории         |

---

## 1. Файл

- `%APPDATA%\XonkyPass\vault.xpv` — база SQLite 3. Пока хранилище открыто, рядом лежат служебные
  `vault.xpv-wal` и `vault.xpv-shm`; при закрытии SQLite переносит данные в основной файл.
- `PRAGMA application_id = 0x58505631` («XPV1»). Файл с другим значением не открывается:
  ошибка `not_a_vault`.
- `PRAGMA user_version` — число применённых миграций. Файл более новой версии не открывается
  (`unsupported_version`), более старой — обновляется при открытии.
- Режимы: `journal_mode = WAL`, `synchronous = FULL`, `secure_delete = ON`, `foreign_keys = ON`.
- При открытии включаются `SQLITE_DBCONFIG_DEFENSIVE` и `trusted_schema = OFF` (подложенный файл не
  может выполнять функции из схемы) и проверяется `PRAGMA quick_check` (ошибка `corrupted`).
- Все таблицы `STRICT`: SQLite не примет значение не того типа.

## 2. Ключи

```
Мастер-пароль ────── Argon2id (параметры калибруются) ─► ключ слота «password» ─┐
Ключ восстановления ─ Argon2id (лёгкий)               ─► ключ слота «recovery» ─┼─► ключ хранилища
                                                                                │   (256 бит, случайный)
                                     слот = XChaCha20-Poly1305(ключ слота, ключ хранилища)
                                                                                ▼
                                              XChaCha20-Poly1305 для каждого поля каждой записи
```

- **Ключ хранилища** — 256 случайных бит. Создаётся один раз и открыто нигде не хранится.
- **Слоты** (как в LUKS): ключ хранилища лежит в нескольких копиях, каждая зашифрована своим ключом слота.
  Смена мастер-пароля перешифровывает только слот `password`, а не записи.
- **Неверный пароль** определяется по ошибке проверки подлинности при расшифровке слота. Отдельного
  «проверочного хэша» нет. Неверный пароль и испорченный слот неотличимы.
- Мастер-пароль берётся как байты UTF-8, без нормализации Unicode.

### 2.1 Argon2id

Argon2id версии 0x13, соль 16 случайных байт (новая при каждой записи слота), результат 32 байта.

| Слот       | Память (m) | Проходы (t)  | Потоки (p) | Почему                                                   |
| ---------- | ---------- | ------------ | ---------- | -------------------------------------------------------- |
| `password` | 64 МиБ     | от 3 до 64   | 4          | `t` подбирается при создании так, чтобы вывод ключа занимал ~0,6 с; ниже 3 не опускается |
| `recovery` | 19 МиБ     | 2            | 1          | в ключе 128 случайных бит, перебор бессмыслен            |

Потоки считаются параллельно, поэтому на современном процессоре проход по 64 МиБ занимает около 10 мс
и калибровка выбирает несколько десятков проходов.

Параметры из файла принимаются только в пределах m ≤ 1 ГиБ, 1 ≤ t ≤ 256, 1 ≤ p ≤ 16 и
m × t ≤ 64 МиБ × 256 (иначе `corrupted`): испорченный файл не должен заставить приложение выделить
гигабайты памяти или считать ключ минутами.

### 2.2 Ключ восстановления

128 случайных бит и 12 бит контрольной суммы — старшие 12 бит CRC-16/CCITT-FALSE от этих 16 байт.
Всего 140 бит, они записываются 28 символами Crockford Base32 (`0123456789ABCDEFGHJKMNPQRSTVWXYZ`),
старшие биты первыми, группами по 4:

```
XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX
```

При вводе регистр, пробелы и дефисы не важны, `O` читается как `0`, `I` и `L` — как `1`.
Контрольная сумма ловит опечатку (`invalid_recovery_key`) до запуска Argon2.
Секрет слота — сами 16 байт, а не текст.

## 3. Шифрование

**XChaCha20-Poly1305**, для каждого шифрования — новый случайный nonce (24 байта). Каждое зашифрованное
значение в файле имеет вид:

```
nonce (24 байта) ‖ шифртекст ‖ тег Poly1305 (16 байт)
```

### 3.1 Связанные данные (AAD)

Каждый шифртекст привязан к своему месту: расшифровать его можно только с теми же связанными данными.

```
AAD = "XonkyPass" ‖ lp(контекст) ‖ lp(поле 1) ‖ lp(поле 2) ‖ …
lp(x) = длина x (u32 little-endian) ‖ x
```

| Что шифруется        | Контекст  | Поля                                                                      |
| -------------------- | --------- | ------------------------------------------------------------------------- |
| слот ключа           | `slot`    | `vault_id`, вид слота (`password` / `recovery`), `format_ver` (u32 LE)    |
| метаданные записи    | `item`    | `vault_id`, `item_id` (16 байт), `meta`, `format_ver`                     |
| секреты записи       | `item`    | `vault_id`, `item_id`, `secret`, `format_ver`                             |
| снимок в истории     | `history` | `vault_id`, `item_id`, `created_at` строки истории (i64 LE), `format_ver` |

## 4. Таблицы

```sql
vault        (id = 1, vault_id BLOB(16), format_ver, created_at)
key_slots    (kind TEXT PK, params TEXT JSON, wrapped_key BLOB)
items        (id BLOB(16) PK, meta BLOB, secret BLOB, created_at, updated_at, deleted_at, revision)
item_history (id INTEGER PK, item_id → items, data BLOB, created_at)
item_usage   (item_id PK → items, use_count, last_used_at)
```

Даты — unix-время в миллисекундах. `items.id` — UUIDv7. `deleted_at` не NULL — запись в корзине.
`revision` растёт при каждом изменении (задел под синхронизацию). Удаление записи удаляет её историю
и счётчики (`ON DELETE CASCADE`). Полная схема — [`0001_init.sql`](../crates/core/migrations/0001_init.sql).

### 4.1 Параметры слота (`key_slots.params`)

```json
{ "kdf": "argon2id", "version": 19, "m_kib": 65536, "t": 3, "p": 4, "salt": "<32 hex-символа>" }
```

Поле `kdf` выбирает вид слота: так позже добавится слот Windows Hello.

## 5. Содержимое записей

Метаданные и секреты — JSON в UTF-8, каждый шифруется отдельно. Поле `v` в метаданных описывает версию
и метаданных, и секретов: они всегда пишутся вместе. Неизвестные поля при чтении пропускаются,
отсутствующие считаются пустыми.

**Логин**, `items.meta` — нужно для списка и поиска:

```json
{
  "v": 1,
  "kind": "login",
  "title": "GitHub",
  "username": "user@example.com",
  "urls": ["github.com"],
  "apps": ["GitHubDesktop.exe"],
  "tags": ["работа", "dev"],
  "favorite": true,
  "has_totp": true
}
```

`has_totp` хранилище всегда выставляет само, по секретной части.

**Логин**, `items.secret` — расшифровывается только по явному действию:

```json
{
  "password": "…",
  "totp": "otpauth://totp/…",
  "notes": "…",
  "fields": [{ "name": "PIN", "value": "1234", "hidden": true }]
}
```

**Заметка**, `items.meta` (текст лежит здесь, чтобы по нему работал поиск):

```json
{ "v": 1, "kind": "note", "title": "Wi-Fi дома", "body": "…markdown…", "tags": ["дом"], "favorite": false }
```

Секреты заметки — тот же объект, обычно пустой (зарезервирован под скрытые поля).

**Снимок в истории**, `item_history.data`:

```json
{ "v": 1, "updated_at": 1764000000000, "meta": { "kind": "login", "…": "…" }, "secret": { "…": "…" } }
```

`updated_at` — когда эта версия была сохранена; `item_history.created_at` — когда её заменила новая.
Снимок пишется, если изменились секреты или метаданные; смена только тегов или отметки «избранное»
историю не засоряет. Хранятся 50 последних версий записи.

### 5.1 Нормализация

Перед сохранением хранилище приводит поля к единому виду:

- пробелы по краям названия, логина, сайтов, приложений и названий полей убираются; в пароле сохраняются;
- теги: без `#` в начале, пробелы заменяются на `-`; повторы без учёта регистра убираются,
  сохраняется написание первого;
- логин без названия называется по первому сайту или приложению, заметка — по первой строке текста;
- ограничения длины и количества — `xonkypass_core::limits`.

## 6. Что лежит открыто

- `vault_id`, версия формата, дата создания хранилища;
- параметры Argon2 и соли слотов;
- идентификаторы записей (UUIDv7 содержит время создания), даты создания, изменения и удаления, `revision`;
- число и даты версий в истории каждой записи, счётчики использования;
- размеры шифртекстов (примерная длина содержимого).

Названия, логины, сайты, приложения, теги, тексты заметок, пароли, коды 2FA и дополнительные поля
зашифрованы.

## 7. От чего это защищает

**Защищает** от того, у кого есть файл, но нет мастер-пароля или ключа восстановления:

- прочитать любое содержимое записей;
- незаметно подменить данные: перенести шифртекст в другую запись, поле или хранилище, поменять
  идентификатор записи, перенести историю между записями, изменить дату снимка, подложить слот
  из другого хранилища — всё это обнаруживается при расшифровке (ошибка `damaged`, а запись попадает
  в список повреждённых `ItemList::damaged`);
- ослабить параметры Argon2 в файле: ключ слота изменится, и слот просто не откроется.

**Не защищает** (ограничения шифрования по записям; для них нужен доступ к файлу на запись):

- от удаления записей или версий истории;
- от отката записи или всего файла к более старой версии того же хранилища (например, из копии);
- от переноса записей в корзину и обратно, изменения дат и счётчиков (кроме даты снимка истории);
- от утечки сведений из раздела 6.

Тот, кто может менять файл хранилища, обычно может подменить и само приложение, поэтому эти
ограничения приняты сознательно.

## 8. Изменение формата

- **Новая миграция схемы:** файл `crates/core/migrations/000N_….sql`, строка в `MIGRATIONS`
  (`crates/core/src/store.rs`) и тест на открытие файла старой версии.
- **Новое поле записи:** добавляется в структуру с `#[serde(default)]`, версия `v` не меняется.
  Несовместимое изменение JSON повышает `v` и требует перевода старых записей.
- **`FORMAT_VERSION`** меняется только вместе с шифрованием или AAD: это требует перешифровать всё хранилище.
